##que significa que recv no respeta fronteras de mensaje?

Significa algo fundamental de TCP/UNIX sockets tipo `SOCK_STREAM`: **los datos son un flujo continuo de bytes, no “mensajes” separados**.

---

## 🧠 Idea clave

Cuando hacés:

```c
send(fd, &a, sizeof(a), 0);
send(fd, &b, sizeof(b), 0);
```

Vos pensás:

> “mandé dos cosas: `a` y después `b`”

Pero el sistema lo ve como:

> “mandé una secuencia de bytes”

---

## 🔴 Entonces `recv` puede devolverte cualquier combinación

Cuando hacés:

```c
recv(fd, buffer, N, 0);
```

Puede pasar cualquiera de estas situaciones:

### Caso 1: todo junto

```c
a + b llegan juntos
```

👉 Un solo `recv` te devuelve ambos

---

### Caso 2: cortado

```c
a llega en partes
```

👉 necesitás varios `recv` para reconstruirlo

---

### Caso 3: mezclado

```c
[a completo] + [mitad de b]
```

👉 exactamente lo que viste en tu `strace`:

```text
"\0\0\0\0\4\0\0\0"
```

Eso probablemente es:

* un `int`
* seguido de otro `int`

en **un solo recv**

---

## ⚠️ Por eso tu código falla

Vos hacés:

```c
recv(fd, &potencial_primo, sizeof(potencial_primo), 0);
recv(fd, &respuesta, sizeof(respuesta), 0);
```

👉 asumís que cada `recv` devuelve exactamente lo que mandaste

💥 Eso **NO está garantizado**

---


## ✅ Cómo se soluciona

Tenés que definir **tu propio protocolo**.

### Opción 1: leer exactamente lo que esperás

```c
recv(fd, &estructura, sizeof(estructura), MSG_WAITALL);
```

👉 Esto bloquea hasta recibir todo

---

### Opción 2: función robusta (mejor práctica)

```c
int recibir_todo(int fd, void *buf, size_t len) {
    size_t total = 0;
    while (total < len) {
        int n = recv(fd, buf + total, len - total, 0);
        if (n <= 0) return n;
        total += n;
    }
    return total;
}
```

---

### Opción 3: mensajes con tamaño (protocolo real)

Mandás:

```c
[int tamaño][datos]
```

---

## 🧩 En tu caso concreto

Deberías hacer algo así:

```c
typedef struct {
    long potencial;
    long cota_inf;
    long cota_sup;
    int cliente;
} tarea;
```

Y:

```c
recv(fd, &t, sizeof(t), MSG_WAITALL);
```

---

## 📌 Resumen

“`recv` no respeta fronteras de mensaje” significa:

> ❌ No hay garantía de que cada `send` corresponda a un `recv`
> ✅ Solo hay un flujo continuo de bytes
